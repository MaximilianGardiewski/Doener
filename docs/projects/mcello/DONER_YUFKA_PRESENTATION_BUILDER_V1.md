# Mcello Döner/Yufka Presentation Builder V1

Status: **PRESENTATION-READY ON LOCAL DEMO DATA**

## Target

The local presentation fixture attaches one `Soße` modifier group only to the six provisional first-party Drehspieß/Döner/Yufka items `warm-013` through `warm-018`. The runtime adapter activates from that exact structured group rather than comparing browser UUIDs with provisional source IDs.

## Confirmed sauce set

The three sauce names confirmed by the owner on 2026-08-18 are:

- Curry
- Knoblauch
- Scharf

No presentation sauce surcharge is invented. No sauce is silently selected as a default. The localhost presentation permits zero to three selections only as a demo interaction policy because the production single-vs-multiple rule has not yet been confirmed.

## Interaction

The Builder reads the normal Mcello modifier inputs rendered by `app.js`. Tapping a sauce updates the existing Mcello selection/domain path first. The Döner/Yufka adapter then rereads checked inputs and redraws only the visual FoodStage.

`data-assembly-visual-layers` is therefore a count of checked confirmed sauce options, not an independent selection model.

## FoodStage

The FoodStage is a deliberately **schematic** browser-generated 3/4 assembly illustration. It is visually different from Pizza's top-down composition and is not a photograph or claim of documentary Mcello food media. Sauce ribbons are visual presentation cues for the three confirmed names; the illustration does not add product ingredients or production recipe claims.

No Adobe/Firefly short URL or other remote concept asset is loaded at runtime. Reduced-motion users get the same visual state without the short pulse animation.

## Responsive inheritance

Desktop uses the full Builder. Smartphone and tablet use the Builder Responsive V3 contract: portrait shows the rotate gate, landscape exposes the guided touch-first Food-Workbench with FoodStage and authoritative action bar remaining visible.
